# Magpie Bridge Protocol

本文档定义协议头标志位含义、内部关系，以及通用指令和应答机制。


## 协议头

协议头第 5 字节（偏移量 4）为类型 Type。


## 类型 Type （1 字节）

高4位用作标志位，低3位用作分包参数变量长度：
    
      0   1   2   3   4   5   6   7
    +---+---+---+---+---+---+---+---+
    | A | B | C | D |               |
    | C | I | M | S |    EXT LEN    |
    | K | D | D | N |               |
    +---+---+---+---+---+---+---+---+

### 标志位解析

- **A=1** 表示是应答包（数据应答 "COPY" 必须 D=1；系统指令应答 SYN!/ACK!/PONG/FIN! 为 D=0）；
- **B=1** 表示服务器桥接包（包括与服务器握手、要求转发），代表协议头中包含两个 4 字节整数，依次为 target 和 source (Bridge ID，门牌号)；
- **C=1** 表示协议头含有 command 指令信息 (4 bytes)；
- **D=1** 表示协议头含有序列号字段 sn (4 bytes)；D=1 仅用于普通数据包及其数据应答 "COPY"（需要 sn 配对确认），系统指令（SYN?/SYN!/ACK!/PING/PONG/FIN?/FIN!）一律 D=0；分包参数 (index, count) 是否存在由 E 决定（见下），其中 count 是分包总数，index 是当前子包序号 (0 <= index < count)；
- **E**: 整数，表示额外扩展的分包参数 (index, count) 变量的长度，取值范围如下：
	- 0: 无参数（无需分包的微型数据包，相当于 index=0, count=1）
	- 1: 参数长度为 1 字节（2 <= count < 256)
	- 2: 参数长度为 2 字节 (256 <= count < 65,536)
	- 3: 参数长度为 3 字节 (65,536 <= count < 16,777,216)
	- 4: 参数长度为 4 字节 (16,777,216 <= count < 4,294,967,296)

注意：E 的允许取值范围是 0～4，其余取值（5~7）未定义，收到此类包直接判定为错误包；同时 E>0 而 D=0（有分包参数却无 sn）的组合同样判定为错误包。

因此，分包参数长度 E 对应 5 种规格的消息/文件包，分别是：

| E | Description | Min     | Max     |       |
|---|:-----------:|--------:|--------:|-------|
| 0 | mini 消息包  |       0 |  1024 B | ✅    |
| 1 | 小文件       |  1025 B | 256 KiB | _保留_ |
| 2 | 普通文件     | 256 KiB |  64 MiB | ✅     |
| 3 | 大文件       |  64 MiB |  16 GiB | _弃用_ |
| 4 | 超大文件     |  16 GiB |   4 TiB | ✅     |

虽然 1 和 3 也是 E 允许的取值范围，然而基于字节对齐的考虑，在实际应用中并不会启用，
所以打包的时候只会有 3 种规格：0、2、4，但为了兼容性，校验的时候仍应该允许取值 0~4。

包上限计算公式：

|         |  count × 1024 |                     |
|--------:|--------------:|--------------------:|
| 256 KiB |    256 × 1024 |           262,144 B |
|  64 MiB |  65536 × 1024 |        67,108,864 B |
|  16 GiB | (2^24) × 1024 |    17,179,869,184 B |
|   4 TiB | (2^32) × 1024 | 4,398,046,511,104 B |

> 注：上表为各规格**标称上限**（整值便于记忆），精确上限 = count 最大值 × 1024 = 标称值 − 1 KiB；
> 达到标称值时 count 已超出当前 E 的表示范围（如 64 MiB 需 count=65,536，2 字节装不下），
> 打包时自动升档（见下方 calcExt），校验不锁死区间。

### 关于 E 在实际应用中的取值说明

有一点需要特别注意：上面的 E 所对应的文件大小区间其实是可以向下兼容的，
也就是说 2 字节的 (index, count) 也能承载原本 1 字节的区间，
同样地，4 字节的 (index, count) 更是能同时承载 1/2/3 字节的区间，
校验时不应将其锁死在上述表格的区间内。

实际应用中的计算公式/代码如下：

```dart
/// 根据分包总数 count 计算所需宽度 E
static int calcExt(int count) {
    if (count >= 65536) {
        return 4;
    } else if (count >= 2) {
        return 2;
    } else {
        assert(count == 1, 'packet count error: $count');
        return 0;
    }
}
```

另外，实际应用中从 type 中获取 E 的值使用的掩码是 ```0000 0111```，计算公式如下：

```dart
    E = type & 0x07;
```

这意味着 type 的低 4 位实际上只用到最低的 3 位，
因为实际上不可能用得到 8 字节的 (index, count)，
所以目前版本中第 4 位恒为 0（但是校验的时候不要去管它）；
考虑到未来有可能会利用这个位来做其他 flag，所以校验 E 的时候不要用 ```E = type & 0x0F```。

### 内部关系

1. 数据应答包（"COPY"，A=1, D=1）必定携带 sn（及可能的 index, count），用于与原始数据包配对确认；系统指令应答（SYN!/ACK!/PONG/FIN!，A=1, D=0）无需 sn；
2. 如果 B=0，则表示是客户端直连的数据包，中间不经过服务器，所以协议头不含 bid 字段（target/source 字段不存在）；
3. 如果 C=1，则此协议头含有 command 信息（4字节），通常用作额外参数（具体值在后面定义）；
4. 如果 D=1，则表示该数据包存在 sn 以及可能的 index, count（由 E 决定）；客户端收到 D=1 且 A=0 的普通数据包时需要回复数据应答 "COPY"；
5. 如果 E>0，则必定 D=1，因为需要分片的数据包一定有序列号，此时接收方需结合 sn 与 index 区分各子包；反之 D=0 时 E 必为 0（不存在有 index/count 却无 sn 的包）。


## Command

Command 本质为一个 32 位无符号整数，取值范围 1 ~ 4294967295；除系统保留指令外，应用层可自由使用其余任意值定义自己的指令集。

系统指令从该空间中选取少量保留值，为便于识别，采用将可读字符串按网络字节序（大端）转换为整数的方式定义，如 "SYN?" = 0x53594E3F、"DATA" = 0x44415441。

数值 0 保留表示空 command（对应 C=0，字段不存在，含义等同 "DATA"）；command 具体值是否属于系统指令、如何应答，由服务器管理线程判断。

如果标志位 C=1，则协议头末尾 4 字节为 command 信息：

| Value  | Flags                    | Desc                        |
|--------|--------------------------|-----------------------------|
| "SYN?" | A=0, C=1, D=0, E=0       | 第1次握手                    |
| "SYN!" | A=1, C=1, D=0, E=0       | 第2次握手（应答）             |
| "ACK!" | A=1, C=1, D=0, E=0       | 第3次握手（成功连接）          |
| "FAIL" | A=1, C=1, D=0, E=0       | 失败（分配 bid 失败 / 连接未确认） |
| "DATA" | A=0,      D=1            | 普通数据包（可选，C 可 0 可 1） |
| "COPY" | A=1, C=1, D=1            | 确认收到（数据应答包）         |
| "PING" | A=0, C=1, D=0, E=0       | 发起心跳                     |
| "PONG" | A=1, C=1, D=0, E=0       | 心跳应答                     |
| "FIN?" | A=0, C=1, D=0, E=0       | 第1次挥手                    |
| "FIN!" | A=1, C=1, D=0, E=0       | 第2次挥手（应答）             |
| -      | -                        |                            |
| "NOOP" | -                        |                            |
| "USER" | -                        | 用户自定义                   |

> 注：系统指令（SYN?/SYN!/ACK!/PING/PONG/FIN?/FIN!）均为 D=0，不携带 sn，发送方无需维护等待应答的队列；
> command 为空时，其含义等同于 "DATA"（默认值）；
> 仅普通数据包及其数据应答 "COPY" 使用 D=1（需要 sn 配对确认）。因此 **D 位可直接作为“发送后是否需要等待应答”的判据**。

1. 所有数据包（包括系统指令包和普通数据包）都可选择是否通过服务器转发，所以 B 可以是 1 也可以是 0；
2. 普通数据包（A=0, D=1）体积最大，为了最大限度地减小被中间网络节点分片的可能性，可以选择 C=0 的方式发送，即不需要 command 字段，接收方同样回复应答包 "COPY"（A=1, C=1, D=1）；
3. 如果 C=1，则 command 不能为空，否则判定为错误包。
