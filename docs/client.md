# Magpie Client（客户端示例）

> Magpie 客户端示例，演示桥接通讯测试流程。两个客户端 A 和 B。

## 1. 客户端 A（被动模式）

```mermaid
flowchart TD
    A1[绑定 UDP] --> A2[向服务器申请 bid]
    A2 -- "收到 FAIL" --> A2R[重新申请或放弃]
    A2 -- "成功" --> A3[显示 bid 及服务器返回的 socket 信息]
    A3 --> A4[等待其他客户端发送数据]
    A4 --> A5[等待期间维护心跳机制]
    A5 --> A6[收到数据后按协议自动回复应答包]
    A6 --> A7[展示收到的信息<br/>包括发送方 bid 或 socket 信息]
    A7 --> A4
```

1. 绑定 UDP，然后向服务器申请 bid（若收到 "FAIL" 则重新申请或放弃）；
2. 将获取到的 bid 显示出来，包括服务器返回的 socket 信息；
3. 等待其他客户端发送数据；
4. 等待期间需要维护心跳机制；
5. 收到其他客户端发送的数据后按照协议自动回复应答包；
6. 将收到的信息展示出来，包括发送方信息（bid 或 socket 信息）等。

## 2. 客户端 B（主动模式）

```mermaid
flowchart TD
    B1[绑定 UDP] --> B2[向服务器申请 bid]
    B2 -- "收到 FAIL" --> B2R[重新申请或放弃]
    B2 -- "成功" --> B3[显示获取的 bid 及 socket 信息]
    B3 --> B4[等待用户输入接收方信息<br/>bid 或 socket 信息]
    B4 --> B5[输入接收方 bid 及要发送的文本内容]
    B5 --> B6[构建 BridgePacket，交由服务器转发]
    B6 --> B7[等待对方返回应答包]
    B7 -- "收到 COPY" --> B8[更新消息状态为已接收]
    B8 --> B4
```

1. 绑定 UDP，然后向服务器申请 bid（若收到 "FAIL" 则重新申请或放弃）；
2. 将获取的 bid 显示出来，包括服务器返回的 socket 信息；
3. 等待用户输入接收方信息（bid 或 socket 信息）；
4. 等待用户输入接收方的 bid，以及要发送的文本内容；
5. 构建 BridgePacket，交由服务器转发；
6. 等待对方返回应答包，然后更新消息状态为“已接收”。
